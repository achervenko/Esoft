# База данных Warehouse

Схема Prisma: `backend/prisma/schema/warehouse/warehouse.prisma`.
Init SQL и manifest находятся в `backend/prisma/packages/warehouse`.
Пакет требует Core и Orders; канонические заказы принадлежат модулю Orders.

## Модели

| Модель                                       | Ответственность                                   |
| -------------------------------------------- | ------------------------------------------------- |
| WarehouseItem                                | Артикул, название, базовая единица, активность    |
| Warehouse, WarehouseStorageLocation          | Склады и места хранения                           |
| WarehouseBalance                             | Физическое количество товара в месте              |
| WarehouseItemExternalLink                    | Подтверждённое сопоставление товара источника     |
| WarehouseExternalWarehouse                   | Административное сопоставление склада источника   |
| WarehouseReceipt, WarehouseReceiptLine       | Ожидающий документ прихода и строки               |
| WarehouseReceiptPlacement                    | Фактическое размещение со снимками товара и места |
| WarehouseIssueSheet, WarehouseIssueSheetLine | Задание на выдачу и строки                        |
| WarehouseIssue, WarehouseIssuePosition       | Выдача и фактические списания                     |
| WarehouseIssueRequest                        | Ключ команды, hash и сохранённый ответ выдачи     |
| WarehouseTransfer                            | Перемещение со снимками до и после                |
| WarehouseStockAdjustment                     | Административная корректировка                    |
| WarehouseStockAdjustmentAttachment           | Неизменяемые документы корректировки              |
| WarehouseStockAdjustmentNoop                 | Результат нулевой корректировки для replay        |

Заказ 1С в строке прихода хранится только как `orderSnapshot` — исходные сведения
документа. Это не справочник заказов и не связь с `CustomerOrder`.

## Типы и ограничения

ID складских объектов — PostgreSQL bigint / Prisma BigInt, в JSON — строки.
Пользователи ссылаются на Core `user` (text ID). Количество — numeric(14,3),
арифметика выполняется через Decimal; единица базовая, пересчёта упаковок нет.
Баланс неотрицателен, строки документов и движения строго положительны.
CHECK-ограничения определены в SQL и отмечены в Prisma.

Пара `(item_id, storage_location_id)` уникальна. Нулевая запись баланса сохраняется.
Артикул уникален; имя склада уникально; имя места уникально внутри склада.
Номер строки листа положителен и уникален внутри листа.
Смена единицы товара запрещена при наличии баланса или строки листа.
Даты операций используют timestamptz(6); дата накладной — date.
FK справочников и исторических документов используют RESTRICT. Строки и
размещения прихода следуют жизненному циклу документа согласно init SQL.

## Транзакционные контракты

Изменения количества выполняются только через Stock в транзакции вызывающего
бизнес-сервиса. Документ, количества и общий аудит фиксируются атомарно.
Stock блокирует товар, места и пары балансов в стабильном порядке, включая ещё
не созданные балансы. Полный протокол: [Stock transactions](../backend/src/warehouse/stock/STOCK-TRANSACTIONS.md).

Импорт/создание прихода меняет ожидающий документ. Только размещение увеличивает
физическое количество. Связывание ручного прихода с 1С не создаёт второго движения.
Входящие события принадлежат общему integration_events.

Выдачи, перемещения и корректировки защищены ключами запроса и hash команды.
Выдача хранит JSON ответа; нулевая корректировка сохраняет результат отдельно,
без движения. Иное содержимое с использованным ключом отклоняется.
Исторические снимки сохраняют отображаемые данные независимо от переименований.
