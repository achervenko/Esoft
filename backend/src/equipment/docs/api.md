# API

## Общие замечания

- Базовый префикс модуля: `/api/equipment`
- Идентификатор в URL — это пользовательский `visibleId`, а не внутренний `equipment.id`
- Чтение оборудования, истории и опций формы требует `equipment.read`
- Создание и редактирование оборудования требует `equipment.edit`
- Просмотр списка файлов, скачивание и preview требуют `equipment.read` + `files.read`
- Загрузка, удаление и назначение основного файла требуют `equipment.edit` + `files.manage`
- Права проверяет глобальный guard по активным ролям; отсутствие сессии даёт `401`, недостаток прав — `403`
- Route-параметры `visibleId` и `fileId` должны быть положительными безопасными целыми числами; нарушение возвращает `400 ROUTE_ID_INVALID`
- Ошибки валидации и бизнес-ошибки возвращаются как `400` или `409`

## GET /api/equipment

Получение списка оборудования.

### Назначение

Возвращает реестр оборудования для таблицы списка.

### Параметры

Необязательные query-параметры:

- `page` — номер страницы от 1 до 1 000 000; по умолчанию `1`.
- `limit` — размер страницы от 1 до 100; по умолчанию `100`.
- `sort` — `visibleId`, `name`, `inventoryNumber`, `serialNumber`,
  `manufacturer`, `model` или `statusLabel`; по умолчанию `visibleId`.
- `direction` — `asc` или `desc`; по умолчанию `asc`.

`page` и `limit` передаются строками из цифр; пустые, дробные, отрицательные
и выходящие за диапазон значения отклоняются. При равных значениях основного
поля порядок определяется внутренним `equipment.id ASC` независимо от `direction`.
Поиск и фильтры в `EquipmentListQuery` не предусмотрены.

Пример: `GET /api/equipment?page=2&limit=50&sort=name&direction=asc`.

### Ответ

Объект `{ items, total, page, limit }`, где `total` — общее число записей,
а `items` — массив оборудования текущей страницы. За пределами списка
возвращается пустой `items` с сохранением `total`.

Поля элемента `items`:

- `id`
- `visibleId`
- `name`
- `inventoryNumber`
- `serialNumber`
- `manufacturer`
- `model`
- `status`
- `statusLabel`

### Ошибки

- `400` — некорректные `page`, `limit`, `sort` или `direction` (без отдельного прикладного кода ошибки).

## GET /api/equipment/create-options

Получение справочников для формы создания и редактирования.

### Назначение

Возвращает набор данных, необходимых для построения формы оборудования.

### Параметры

- `visibleId?` — пользовательский номер текущего оборудования: положительное
  безопасное целое число. Передаётся при редактировании.
- Отсутствующий параметр передаётся сервису как `undefined`; пустое значение
  (`?visibleId=`) не считается отсутствующим и отклоняется.

Без `visibleId` выдаются активные опции и следующий доступный пользовательский
номер. При переданном `visibleId` оборудование должно существовать; в опции
также включаются его текущие связанные записи, даже если они уже неактивны.
Это позволяет сохранить текущие значения формы редактирования.
Поле `nextVisibleId` в этом случае содержит переданный номер оборудования.

### Ответ

Объект:

- `nextVisibleId`
- `manufacturers`
- `models`
- `countries`
- `sections`
- `employees`
- `statuses`

### Ошибки

- `400 ROUTE_ID_INVALID` — `visibleId` передан, но не является положительным
  безопасным целым числом.
- `404` — оборудование с переданным `visibleId` не найдено.

## GET /api/equipment/:visibleId

Получение карточки оборудования.

### Параметры

- `visibleId` — целый положительный номер оборудования в URL

### Ответ

Полная карточка оборудования:

- идентификаторы и названия;
- модель и производитель;
- страна;
- даты;
- статус и человекочитаемая подпись статуса;
- местоположение;
- ответственный сотрудник;
- текстовые поля.

### Ошибки

- `404` — оборудование не найдено

### Ответ

Массив записей:

- `id`
- `action`
- `createdAt`
- `fieldName`
- `oldValue`
- `newValue`
- `timeZone`
- `user`

### Ошибки

- `404` — оборудование не найдено

## POST /api/equipment

Создание оборудования.

### Назначение

Создаёт новую запись оборудования и возвращает полную карточку.

### Тело запроса

- `visibleId?`
- `name`
- `modelId`
- `specifications?`
- `serialNumber?`
- `inventoryNumber`
- `countryId?`
- `manufactureYear?`
- `commissioningDate?`
- `issueDate`
- `sectionId`
- `responsibleEmployeeId`
- `status`
- `operationText?`
- `notes?`

### Ответ

Полная карточка оборудования в том же формате, что `GET /api/equipment/:visibleId`.

### Ошибки

- `400` — некорректные данные формы
- `400` — модель, участок, страна или ответственный не существуют
- `400` — ответственный сотрудник неактивен
- `409` — `visibleId` уже занят
- `409` — `inventoryNumber` уже занят

## PUT /api/equipment/:visibleId

### Назначение

Изменяет существующее оборудование и возвращает обновлённую карточку.

### Параметры

- `visibleId` — текущий пользовательский номер оборудования в URL

### Тело запроса

Такое же, как у `POST /api/equipment`.

### Ответ

Полная карточка оборудования.

### Ошибки

- `404` — оборудование не найдено
- `400` — некорректные данные формы
- `400` — модель, участок, страна или ответственный не существуют
- `400` — ответственный сотрудник неактивен
- `409` — новый `visibleId` уже занят
- `409` — `inventoryNumber` уже занят

## GET /api/equipment/:visibleId/files

Получение списка файлов оборудования.

### Назначение

Возвращает файлы, привязанные к оборудованию как к владельцу в storage-модуле.

### Ответ

Массив объектов файла storage-модуля.

Каждый объект содержит метаданные файла, используемые фронтендом для отображения списка и скачивания:

- идентификатор файла;
- имя файла;
- тип документа;
- размер;
- дату создания;
- автора или источник загрузки;
- служебные поля storage-модуля, необходимые для работы с файлом.

### Ошибки

- `404` — оборудование не найдено

## POST /api/equipment/:visibleId/files

Загрузка файла оборудования.

### Назначение

Загружает файл в storage-модуль и пишет аудит загрузки в модуле `EQUIPMENT`.

### Тело запроса

`multipart/form-data`:

- `file`
- `documentType`

### Ответ

Созданная запись файла из storage-модуля.

Ответ содержит метаданные загруженного файла и данные, необходимые для его последующего отображения в списке файлов оборудования.

### Ограничения

- размер файла ограничен `MAX_FILE_SIZE_BYTES`
- требуется право `equipment.edit` + `files.manage` (глобальный guard)

### Ошибки

- `404` — оборудование не найдено
- ошибки валидации storage-модуля

## GET /api/equipment/:visibleId/files/:fileId/download

Скачивание файла оборудования.

### Параметры и права

- `visibleId` — пользовательский номер оборудования;
- `fileId` — идентификатор файла, принадлежащего этому оборудованию;
- оба идентификатора — положительные безопасные целые числа;
- одновременно требуются `equipment.read` и `files.read`.

### Ответ

`200` — поток содержимого файла, не JSON. `Content-Type` соответствует файлу,
`Content-Disposition: attachment` содержит имя для скачивания. `Content-Length`
передаётся, если известен. `Cache-Control: private, max-age=0, no-cache`.

### Основные ошибки

- `400 ROUTE_ID_INVALID` — некорректный идентификатор;
- `401` — нет сессии;
- `403 FORBIDDEN` — отсутствует хотя бы одно необходимое право;
- `404 EQUIPMENT_NOT_FOUND` — оборудование не найдено;
- `404` — файл отсутствует, удалён или принадлежит другому владельцу.

## GET /api/equipment/:visibleId/files/:fileId/preview

Просмотр PDF или изображения в браузере.

### Параметры и права

- `visibleId`, `fileId` — положительные безопасные целые числа;
- необязательный query-параметр `size`: `small` или `medium`;
- одновременно требуются `equipment.read` и `files.read`.

### Ответ

`200` — поток файла с `Content-Disposition: inline`. Для изображения с заданным
`size` возвращается оптимизированное изображение `image/webp`; без размера —
исходное изображение. Для PDF возвращается `application/pdf`, размер preview
не применяется. `Content-Length` передаётся, если известен.

Для оптимизированного изображения используется
`Cache-Control: private, max-age=31536000, immutable`, для остальных preview —
`private, max-age=86400`.

### Основные ошибки

- `400 ROUTE_ID_INVALID` — некорректный идентификатор;
- `400 INVALID_PREVIEW_SIZE` — непустой `size` отличается от `small` и `medium`;
- `400` — формат файла не поддерживает preview (доступны PDF и изображения);
- `401` — нет сессии;
- `403 FORBIDDEN` — отсутствует хотя бы одно необходимое право;
- `404 EQUIPMENT_NOT_FOUND` — оборудование не найдено;
- `404` — файл отсутствует, удалён или принадлежит другому владельцу.

## DELETE /api/equipment/:visibleId/files/:fileId

Мягкое удаление файла оборудования с записью аудита в `EQUIPMENT`.

### Параметры и права

- `visibleId`, `fileId` — положительные безопасные целые числа;
- тело запроса не требуется;
- одновременно требуются `equipment.edit` и `files.manage`.

### Ответ

`200` — метаданные удалённого файла: `id`, `originalName`, `displayName`,
`documentType`, `mimeType`, `sizeBytes` (строка), `isPrimary`, `createdAt`,
`deletedAt`. Даты сериализуются в ISO-формате; `deletedAt` заполнен.

Файл исключается из активного списка. При удалении основного файла Storage
назначает следующий основной файл того же типа, если это допускает политика
типа документа и есть подходящий файл. Физический объект этой операцией не удаляется.

### Основные ошибки

- `400 ROUTE_ID_INVALID` — некорректный идентификатор;
- `401` — нет сессии;
- `403 FORBIDDEN` — отсутствует хотя бы одно необходимое право;
- `404 EQUIPMENT_NOT_FOUND` — оборудование не найдено;
- `404` — файл отсутствует, уже удалён или принадлежит другому владельцу;
- `409 STORAGE_FILE_IMMUTABLE` — изменение документа запрещено.

## PATCH /api/equipment/:visibleId/files/:fileId/primary

Назначение основного файла для данного оборудования и типа документа.

### Параметры и права

- `visibleId`, `fileId` — положительные безопасные целые числа;
- тело запроса не требуется;
- одновременно требуются `equipment.edit` и `files.manage`.

### Ответ

`200` — метаданные файла в том же формате, что у удаления, с `isPrimary: true`
и `deletedAt: null`. Прежний основной файл того же типа теряет этот признак.
Повторное назначение уже основного файла возвращает его без новой записи аудита.
Изменение основного файла фиксируется в аудите `EQUIPMENT`.

### Основные ошибки

- `400 ROUTE_ID_INVALID` — некорректный идентификатор;
- `400 UNSUPPORTED_PRIMARY_FILE` — политика типа документа запрещает назначение основного файла;
- `401` — нет сессии;
- `403 FORBIDDEN` — отсутствует хотя бы одно необходимое право;
- `404 EQUIPMENT_NOT_FOUND` — оборудование не найдено;
- `404` — файл отсутствует, удалён или принадлежит другому владельцу;
- `409 STORAGE_FILE_IMMUTABLE` — изменение документа запрещено.
