# Места хранения

Storage Locations ведёт плоский справочник `WarehouseStorageLocation` отдельно
от Catalog и Stock. Используется существующая таблица, миграций нет.
Компонент подключается вместе с WarehouseModule при включённом `warehouse`.

## API и доступ

Префикс `/api/warehouse/storage-locations`:

- `GET /` — список, permission `warehouse.storage-locations.read`.
- `GET /:id` — карточка, то же право; дополнительно `hasStock` сообщает
  о наличии положительного остатка для предупреждения перед деактивацией.
- `POST /` — создать, permission `warehouse.storage-locations.manage`.
- `PATCH /:id` — изменить, то же право. DELETE отсутствует.

Оба права назначены admin и storekeeper. Управление дополнительно проверяет
пользователя, banned и актуальные права внутри транзакции под блокировкой пользователя.
HTTP guard проверяет чтение и запись. BigInt ID передаются десятичными строками.

POST принимает `code`, `name`, необязательное `isActive` (по умолчанию true).
PATCH принимает непустое подмножество этих полей. Строки trim, длина кода 1–100,
названия 1–255. Неизвестные поля, null и неверные типы запрещены.
Уникальность кода обеспечивает БД; конфликт — 409
`WAREHOUSE_STORAGE_LOCATION_CODE_CONFLICT`, отсутствие — 404
`WAREHOUSE_STORAGE_LOCATION_NOT_FOUND`.

Список принимает `search` (код/название, регистронезависимый буквальный поиск),
`isActive=true|false` (без параметра — все), `page=1`, `limit=50` (до 100),
`sortBy=code|name|isActive`, `sortOrder=asc|desc`. По умолчанию code ASC;
второй ключ id ASC. Ответ `{items,total,page,limit}` читается в RepeatableRead.

## Изменения и история

PATCH блокирует место FOR UPDATE и изменяет только переданные поля.
Создание и изменение атомарны с AuditLogService: WAREHOUSE,
`warehouse_storage_location`, прежние и новые значения полей.
Ошибка аудита откатывает запись. GET не аудируется.

Деактивация разрешена при ненулевом остатке. Компонент не изменяет остатки,
резервы и историю, не выполняет движения и не вычисляет их количества.
`hasStock` — только проверка наличия положительной строки остатка; это
информационный снимок, не запрет деактивации.

Issues и IssueSheets проверяют активность в своих транзакциях. Внутренний Stock
проверяет существование, а допустимость операций определяет вызывающий модуль.
Административные Adjustments сохраняют существующее исключение: доступны admin
и могут исправлять остатки в неактивном месте.

Иерархия, импорт, генерация кодов и новые поля не добавлены. Текущие ID и ссылки
сохраняются. UI находится в «Справочники → Места хранения» и поддерживает поиск,
фильтр активности, сортировку, страницы, создание, изменение и смену активности.
