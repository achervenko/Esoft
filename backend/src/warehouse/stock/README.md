# Склад: Stock

## Назначение и ответственность

Stock хранит и изменяет физическое количество номенклатуры по местам хранения.
Остаток определяется парой «товар + место». Место принадлежит складу; количество
выражено в базовой единице товара. Нулевая запись сохраняется, отсутствующая
запись отличается от нулевого остатка.

Stock предоставляет чтение отдельных балансов, сумм по товару и агрегированного
списка «товар + склад». Распределение показывает физическое количество, свободную
часть, резервы, заимствования и нехватку.

Приходы, выдачи, перемещения, резервы и административные корректировки — отдельные
бизнес-компоненты. Они проверяют права, состояние документов, активность записей,
правила резервов и повторное выполнение команд. Stock выполняет физическое
изменение и его аудит в транзакции вызывающего компонента.

## Архитектура

Компонент подключается через `WarehouseStockModule` в составе пакета `warehouse`.
Модуль экспортирует `WarehouseStockService`; `WarehouseModule` предоставляет его
остальным складским компонентам. Зависимости: Prisma, аудит, хранилище файлов
и структура складов.

| Компонент                                                  | Ответственность                                                           |
| ---------------------------------------------------------- | ------------------------------------------------------------------------- |
| `stock.service.ts`                                         | Фасад чтения, увеличение, уменьшение и перемещение физического количества |
| `stock-query.service.ts`                                   | Чтение балансов, фильтры, пагинация и суммы                               |
| `stock-overview.service.ts`                                | Агрегированный список и распределение с резервами                         |
| `stock-locks.ts`                                           | Общий протокол блокировок товара, мест и балансов                         |
| `stock.types.ts`, `stock.validation.ts`                    | Типы, DTO и проверка внутренних параметров                                |
| `stock-http.validation.ts`, `stock-overview.validation.ts` | Проверка HTTP-параметров                                                  |
| `stock.controller.ts`, `stock-overview.controller.ts`      | HTTP-чтение с проверкой разрешений                                        |

Хранение: `warehouse_balances`, связи с `warehouse_items` и
`warehouse_storage_locations`; распределение читает также
`warehouse_project_reservations`. Пара `(item_id, storage_location_id)` уникальна.
ID передаются bigint-строками, количества — decimal-строками без округления.

## Основные интерфейсы

HTTP-чтение требует сессию и `warehouse.stock.read`. При отключённом пакете
`warehouse` маршруты не регистрируются.

| Маршрут GET                                                           | Назначение                                         |
| --------------------------------------------------------------------- | -------------------------------------------------- |
| `/api/warehouse/stock`                                                | Отдельные балансы по местам                        |
| `/api/warehouse/stock/items/:itemId/total`                            | Сумма товара по всем складам или выбранному складу |
| `/api/warehouse/stock/items/:itemId/locations/:locationId`            | Один баланс или `null`                             |
| `/api/warehouse/stock-overview`                                       | Список по товару и складу                          |
| `/api/warehouse/stock-overview/items/:itemId/warehouses/:warehouseId` | Распределение товара по местам с резервами         |
| `/api/warehouse/stock-overview/filters/warehouses`                    | Варианты фильтра складов                           |
| `/api/warehouse/stock-overview/filters/storage-locations`             | Варианты фильтра мест                              |

Форматы ответов, фильтры, сортировка, ошибки и выполнение агрегированного запроса:
[STOCK-API.md](STOCK-API.md).

Внутренние методы `receiveStock`, `issueStock` и `moveStock` требуют
`{tx, actorUserId}`. Они не создают собственных транзакций и не проверяют резервы.
HTTP-изменения выполняются через API соответствующих бизнес-компонентов.

## Транзакционные гарантии

- Бизнес-документ, физические изменения, резервы и аудит сохраняются в общей транзакции.
- Все участники записи используют единый порядок блокировок. Он защищает также
  создание ещё отсутствующего баланса и конкурентное изменение единицы товара.
- Ошибка Stock или аудита выходит из callback транзакции и откатывает всю операцию.
- Повтор команды и конфликты транзакций обрабатываются вызывающим компонентом.
- Чтение списка и счётчика согласовано; агрегированное представление читается в `RepeatableRead`.

Полный порядок блокировок, ограничения интеграции и пример вызова:
[STOCK-TRANSACTIONS.md](STOCK-TRANSACTIONS.md). Этот контракт обязателен для
всех сервисов, изменяющих балансы или связанные резервы.

## Тестирование

```powershell
npm run test --workspace backend -- --runInBand warehouse optional-warehouse
npm run build:backend
$env:ESOFT_MODULAR_MIGRATION_TEST = '1'
try {
  node --test tests/scripts/infrastructure/prisma/warehouse-stock.real.integration.test.mjs
} finally {
  Remove-Item Env:ESOFT_MODULAR_MIGRATION_TEST
}
```

Интеграционные тесты используют временный PostgreSQL с `core + orders + warehouse`,
без подключения к рабочей БД. Требуются `initdb` и `pg_ctl`; путь задаётся через
`ESOFT_TEST_PG_BIN`, по умолчанию — `C:/Program Files/PostgreSQL/17/bin`.

Проверяются фильтры и DTO, суммы по местам и складам, стабильная пагинация,
пустые страницы, нулевые остатки с резервами, границы количества, конкурентные
изменения и откат при ошибке аудита.
