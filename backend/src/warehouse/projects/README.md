# Проекты склада временная заглушка

**Статус: временная read-only заглушка. Полноценный Projects-модуль ещё не готов.**

WarehouseProjectsModule предоставляет существующие записи `warehouse_projects`
для выбора проекта в складских формах резервов, выдач и листов выдачи.
Это не канонический справочник проектов предприятия и не интеграция с 1С.
Данные сами не импортируются и не создаются этим API. В пустой БД список пуст.

Микромодуль импортируется только из WarehouseModule и доступен при включённом
`warehouse`. Отдельный optional-модуль `projects` в каталог модулей не добавляется.
Модель и миграции не меняются. ID остаются существующими складскими ID.

## HTTP API

Все маршруты требуют сессию и `warehouse.projects.read` (admin/storekeeper).

- `GET /api/warehouse/projects` — `{items,total,page,limit}`.
- `GET /api/warehouse/projects/:id` — `{id,projectNumber,name,isActive}`.
  Неактивный проект также доступен для чтения исторических данных.
  При отсутствии — 404 `WAREHOUSE_PROJECT_NOT_FOUND`.

Поля DTO: id — каноническая bigint decimal string, projectNumber — номер,
name — необязательное название (`null` допустим), isActive — активность.
Номер и название не разбираются на составные части.

Список принимает:

- `search` — буквальный поиск без учёта регистра по projectNumber/name,
  trim, до 255 символов; `%`, `_` и `\` не являются шаблонами.
- `isActive=true|false`; без параметра возвращаются все записи.
  Для выбора в новых операциях клиент запрашивает `isActive=true`.
- `page=1`, `limit=50`, максимум limit=100; смещение до 2147483647.

Сортировка projectNumber ASC, id ASC. Список и total читаются в одном
RepeatableRead-снимке. Неизвестные и неверные query-параметры — 400
`INVALID_WAREHOUSE_PROJECT_QUERY`. Неверный ID — 400
`WAREHOUSE_STOCK_ID_INVALID` (общая складская проверка ID).
Чтение не записывает аудит. POST/PATCH/DELETE отсутствуют.

## Что ещё не готово

- Создание, изменение, закрытие и удаление проектов.
- Импорт и синхронизация проектов из 1С, внешние GUID и сопоставление.
- Бизнес-правила, жизненный цикл и каноническая модель проекта.
- Миграция складских ссылок на будущий самостоятельный ProjectsModule.

При появлении настоящего ProjectsModule потребуется отдельно спроектировать
сопоставление и миграцию существующих ссылок Reservations/Issues/IssueSheets.
Автоматическая совместимость идентификаторов с 1С не предполагается.
Активность проекта при новых складских мутациях по-прежнему проверяет
соответствующий бизнес-компонент внутри своей транзакции.
