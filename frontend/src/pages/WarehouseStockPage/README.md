# Остатки склада

Экран получает агрегированный список товара по складам через stock-overview.
Поиск, фильтры и оконный рендер поддерживают большие списки. Распределение
открывается в StockDistributionModal: товар, общий физический остаток и
количество по каждому месту.

Один AdminModal используется для просмотра, перемещения, консолидации и
корректировки. Перемещение доступно с warehouse.transfers.manage;
административная корректировка — с warehouse.adjustments.manage.

Формы перемещения и консолидации сохраняют исходную команду в sessionStorage
перед отправкой. При неопределённом результате параметры и закрытие блокируются;
повтор использует исходный requestKey. Корректировка сохраняет также исходные
expectedQuantity, actualQuantity и ID вложений. Документ и причина обязательны.
Успех обновляет распределение и родительский список.

API и транзакционные гарантии: [Stock](../../../../backend/src/warehouse/stock/README.md),
[Transfers](../../../../backend/src/warehouse/transfers/README.md),
[Adjustments](../../../../backend/src/warehouse/adjustments/README.md).

## Строки свободных остатков и резервов

В таблице мест хранения свободный остаток и каждый резерв заказа отображаются отдельными строками, даже если физическое место совпадает. Погрузчик относится к выбранной строке. Для резервной строки дополнительно требуется `warehouse.reservations.manage`; сервер повторно проверяет права.

Форма перемещения получает UUID выбранного резерва либо свободную строку. Пользователь выбирает назначение и количество в пределах этой строки. Для резерва формируется `StockTransferInput.distribution` с нулевой свободной частью и одним выбранным резервом. Свободное количество переносится обычной командой. Серверный контракт смешанного перемещения сохраняется.

Выбранная строка, исходные параметры и `requestKey` сохраняются в механизме незавершённых перемещений. После перезагрузки повтор использует исходный состав. Карандаш каждой строки исправляет её фактическое количество. Форма показывает выбранную часть; команда передаёт полный физический баланс и контекст `portion` для проверки выбранной части. Потребность заказа сохраняется, изменение обеспеченности выполняется сервером атомарно с физической корректировкой.
