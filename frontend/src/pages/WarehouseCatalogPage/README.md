# Склад → Номенклатура

Маршрут: `#/warehouse/catalog`. Доступ по эффективному permission
`warehouse.catalog.manage`, полученному от backend. При выключенном warehouse
backend не возвращает его даже администратору; группа «Склад» скрывается.
Группа сохраняется в sidebar и с единственным пунктом.

Страница использует `/api/warehouse/items`: поиск `q` с debounce 250 мс,
`isActive` (по умолчанию все), серверные `limit=50` / `offset`.
Поиск и фильтр сохраняются в hash query. Сортировку задаёт backend
(`article ASC`, затем `id ASC`), клиент не сортирует отдельную страницу.
Задержка 250 мс применяется только к вводу поиска; фильтр, подгрузка и reload
запрашивают список сразу. Применение фильтра во время ввода использует текущий
текст поиска без дополнительной задержки. При `hashchange` поиск и фильтр
синхронизируются обратно из URL без remount, накопленный список начинается заново с offset=0.

Явных страниц в карточном списке нет. Общий `useIncrementalList` запрашивает
порции по 50 и добавляет их к уже показанным карточкам, сохраняя серверный порядок.
ID используются для дедупликации без преобразования в Number. `ListLoadMore` / `LoadMore`
запускает следующую порцию при приближении к концу списка (IntersectionObserver,
rootMargin=200px). Кнопка «Показать ещё» остаётся ручным и клавиатурным способом
загрузки, в том числе без поддержки observer. Отображается «Показано N из total».

Одновременно выполняется один запрос. Повторное срабатывание observer/кнопки
не пропускает offset; устаревшие callbacks и ответы предыдущего поиска игнорируются.
При ошибке следующей порции карточки остаются видны, автоподгрузка останавливается,
а retry повторяет именно неудачный offset. Пустая порция завершает подгрузку,
даже если сервер вернул прежний total. При открытой форме автоподгрузка приостановлена.
Поиск, фильтр, hash-навигация и успешные мутации/reload перечитывают список с начала.
При дозагрузке уже видимые карточки не заменяются индикатором загрузки.
`loadError` coordinator относится только к начальной загрузке. `loading`
используется для начальной загрузки и ожидания применения debounce поиска;
загрузка следующей порции не переводит основной список в `loading`.
Состояния дозагрузки и её ошибка передаются через `list` в `ListLoadMore`.

Порционная загрузка дополнена оконным рендером через общий `useWindowedGrid`.
В DOM остаются видимые строки, до 100 предшествующих и примерно 50 последующих
позиций (запас округляется вниз до целых строк сетки). Дальние карточки размонтируются;
верхний и нижний отступы сохраняют высоту списка. Высоты смонтированных строк
измеряются, при изменении числа колонок измерения пересчитываются. Короткий список
целиком помещается в окно. ARIA-позиции карточек относятся к накопленному списку.
Метаданные загруженных позиций сохраняются в памяти открытой страницы, чтобы
прокручивать список назад без повторного получения порций. После размонтирования
страницы накопленный список теряется: при возвращении запрос начинается с offset=0.
Отдельного кэша между открытиями страницы нет. HTTP-кэш фотографий очищать не нужно:
размонтирование позволяет браузеру освобождать декодированные изображения, но не
принуждает его немедленно очищать собственный memory/disk cache.

Подключение фотографий пока проверяется отдельной временной сборкой: production
API номенклатуры всё ещё не содержит фото. Для 50 тысяч позиций нужен отдельный
нагрузочный прогон; текущая проверка выполнена на 4003 позициях.
Offset API не предоставляет общего snapshot между порциями: после параллельных
изменений каталога reload возвращает актуальный список.

Создание и PATCH используют `article`, `name`, `unit`, `comment`.
В PATCH уходят только изменённые поля; ID всегда строки.
Статус меняется отдельным `PATCH /:id/status`. Подтверждение требуется только
при переключении «Активна → Неактивна»; повторная активация подтверждения не требует.
Переключатель активности находится только в форме «Изменить» и сохраняет статус сразу через отдельный endpoint, не отправляя черновики остальных полей. Во время операции форма заблокирована. Удаления нет.
Ошибки загрузки отображаются в списке, ошибки сохранения полей и статуса — в форме.

API — `shared/api/warehouse-catalog-api.ts`; coordinator — `useWarehouseCatalog`;
карточки и форма вынесены отдельно. UI использует общие SearchToolbar,
CheckboxFilterModal, AdminModal и подтверждения приложения.

Остатки, резервы, проекты, движения, импорт и синхронизация с 1С здесь отсутствуют.

Карточный список заменяет прежнюю табличную концепцию. В карточке отображаются
артикул, наименование и статичная область под будущее фото. Комментарий и отдельный
статус в списке не выводятся. Неактивные карточки используют общий серый стиль
InactiveSurface из СИЗ. API фотографий пока нет.
