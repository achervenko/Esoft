# СИЗ — frontend

Раздел `#/ppe` предназначен для ведения номенклатуры СИЗ, норм выдачи,
выдачи сотрудникам и просмотра журнала.

## Доступ

Раздел доступен ролям `admin`, `ppe_specialist` и `accounting_specialist`.
Права на чтение, каталог, нормы, размеры сотрудников и выдачу определяются
отдельно в `modules/ppe-permissions`.

Frontend ограничивает интерфейс и маршруты. Backend независимо проверяет
права каждого запроса. Только администратор может вручную выбирать дату выдачи.

## Основные экраны

### Карточка сотрудника

Поиск сотрудника, просмотр размеров, действующих норм, текущего плана
и истории выдачи. Для ролей с правом выдачи доступны нормативная и дополнительная
выдача, одновременная выдача нескольких позиций и выбор фактически выдаваемого
СИЗ. Backend предоставляет рекомендации размеров и предупреждения.

### Нормы

Нормы по должностям и история редакций. В зависимости от прав и состояния нормы
доступны создание первой нормы, новая редакция, редактирование будущей редакции,
завершение действующей и удаление будущей нормы.

Расчёт доступности выдачи и переходов между редакциями выполняет backend.

### Номенклатура

Каталог одежды, обуви, перчаток, головных уборов и прочих СИЗ.
Предусмотрены поиск, фильтры, управление позициями и размерными рядами.
Для одежды размер и ростовка образуют единую размерную комбинацию.

### Журнал

История выдач с локальным поиском и серверными фильтрами. Детали выдачи
показывают сохранённые исторические данные, независимо от изменений справочников.
Для ролей с правом выдачи доступна отмена с обязательной причиной.

## Размеры сотрудников

Размеры редактируются в `#/dictionaries`. Для `ppe_specialist` доступен
ограниченный режим сотрудников без административного управления справочниками.

## Архитектура frontend

HTTP API и типы находятся в `shared/api/ppe`. Общий API-клиент отвечает
за сессию и обработку истечения авторизации.

Основные панели раздела: `CatalogPanel`, `NormsPanel`, `IssuePanel`, `JournalPanel`.
Они управляют состоянием экранов и объединяют отдельные формы, таблицы и диалоги.
Поиск и модели форм отделены от разметки.

Общие элементы интерфейса находятся в `shared`, общие PPE-стили — в `modules/ppe-ui`.
`modules/ppe-ui/usePpeQuery` управляет загрузкой, отменой устаревших запросов и повторной загрузкой.
Сообщения об ошибках API формируются в `modules/ppe-ui/ppe-presentation.ts`.

Справочники загружаются для нужного экрана независимо. В журнале справочные
данные запрашиваются при открытии фильтров; их ошибка не скрывает сами выдачи.

Формы защищают несохранённые изменения. После операций связанные данные
обновляются; серверные расчёты и бизнес-ограничения не дублируются на frontend.
Контракты, размерные правила и переходы норм описаны в
[документации backend-модуля](../../../../backend/src/ppe/README.md).

## Проверка

Команды выполняются из корня проекта:

```bash
npm test --workspace frontend
npm run build --workspace frontend
npm run lint --workspace frontend
```

Тесты охватывают каталог, размеры, нормы, выдачу, права доступа и журнал.
