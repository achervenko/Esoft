# Интеграции

Общий UI интеграций находится во вкладке «Интеграции» пользователей. Доступ — `integrations.manage`; новый пункт sidebar не добавляется.

UI использует общий `/api/integrations`: источники 1С, изменяемое имя, URL и исходящая авторизация, активность и подключённые потоки. Пустая authorization при редактировании сохраняет credentials. Новые source code и системный автор создаются сервером.

Список доступных потоков загружается из реестра. Ключ ограничивается выбранными активными потоками; полный секрет показывается один раз. Endpoint входящих событий отображается для каждого активного потока. Использование источника и последняя успешная обработка берутся из flows, не захардкожены.

Журнал использует состояния PENDING/PROCESSING/PROCESSED/FAILED, показывает код ошибки и число попыток; ручной retry доступен для FAILED. Последний успех означает обработанное событие, а не текущую доступность соединения. Проверка соединения не показывается без предусмотренного адаптером проверочного запроса.

На данный момент продуктовый поток — warehouse.receipts. Новые бизнес-обмены регистрируются своими модулями; интеграции не импортируют доменные документы самостоятельно.

## Структура панели

`ReceiptIntegrationPanel` проверяет доступ и координирует обновление данных, выбранный источник, загрузку, ошибки и блокировку мутаций.
`IntegrationSourcesSection` содержит таблицу источников и форму настройки; `IntegrationKeysSection` — выбор источника, адреса событий, выпуск и отзыв ключей; `IntegrationEventsSection` — фильтр, журнал, страницы и повтор обработки.
`useReceiptIntegrationData` загружает источники, реестр потоков и журнал; `useReceiptIntegrationKeys` загружает ключи выбранного источника. Оба хука отменяют устаревшие запросы.

Изменение настроек источника и его потоков выполняется одним `PATCH /api/integrations/sources/:code`: поля источника, переданные потоки, права системного автора и аудит сохраняются в одной транзакции. Ошибка любого шага откатывает весь запрос. Отсутствующее поле `flows` сохраняет подключения без изменений; переданный массив задаёт полный набор потоков, отсутствующие в нём деактивируются; пустой массив отключает все потоки. Неизменённый поток сохраняется и при временно отсутствующем обработчике, изменение такого потока требует доступного обработчика.

Для источника с потоком `warehouse.receipts` кнопка «Склады 1С» открывает административные сопоставления складов. До обмена указываются точный идентификатор склада 1С и активный склад ESoft. Неизвестный/выключенный склад блокирует импорт; после настройки событие повторяется из журнала. Сохранённую связь нельзя переназначить на другой склад.
