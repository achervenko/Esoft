# Интерфейс интеграций

Административная панель источников 1С, подключённых потоков, входящих API-ключей и журнала событий. Размещается во вкладке «Интеграции» страницы пользователей. Доступ определяется разрешением `integrations.manage`.

Панель использует общий API `/api/integrations`. Доменные модули регистрируют доступные потоки на сервере; интерфейс получает их описание из реестра.

## Компоненты и данные

| Компонент                     | Ответственность                                                              |
| ----------------------------- | ---------------------------------------------------------------------------- |
| `IntegrationsPanel`           | Заголовок и контейнер раздела                                                |
| `ReceiptIntegrationPanel`     | Проверка доступа, выбранный источник, обновление данных и блокировка мутаций |
| `IntegrationSourcesSection`   | Таблица источников и открытие настройки источника или связей складов         |
| `ReceiptSourceForm`           | Название, адрес, авторизация, активность и выбор потоков                     |
| `IntegrationFlowStatus`       | Состояние отдельного потока и пояснение ошибки                               |
| `IntegrationKeysSection`      | Выбор источника, адреса входящих событий, список и отзыв ключей              |
| `ReceiptKeyDialog`            | Выпуск ключа и однократное отображение полного секрета                       |
| `IntegrationEventsSection`    | Фильтр состояний, журнал, страницы и повтор обработки                        |
| `IntegrationWarehousesDialog` | Административные связи складов 1С со складами ESoft                          |

`useReceiptIntegrationData` параллельно загружает источники, реестр потоков и страницу событий. `revision` перезапускает загрузку после изменений. `useReceiptIntegrationKeys` загружает ключи выбранного источника и очищает прежнюю ошибку перед новым запросом. Оба хука отменяют устаревшие запросы через `AbortController`.

Контракты запросов и ответов находятся в [receipt-integration-api.ts](../../shared/api/receipt-integration-api.ts). Складские связи используют отдельный [receipt-integration-warehouses-api.ts](../../shared/api/receipt-integration-warehouses-api.ts).

## Настройка источника

Форма работает с источниками типа `ONE_C`. Сервер создаёт код источника и системного автора. Существующие потоки сохраняют свою версию и конфигурацию; выбор в форме меняет их активность. Новые потоки получают `configVersion=1` и `config={}`.

Реестр определяет название потока, поддерживаемые типы источников и входящие действия. При создании источника изначально выбраны совместимые потоки с входящими действиями. При редактировании выбранными отображаются активные потоки источника.

Доступ к чтению 1С задаётся одним из способов:

- логин и пароль — форма формирует заголовок `Basic` из UTF-8 данных;
- готовое значение заголовка `Authorization`.

Для нового источника credentials обязательны. При редактировании пустые поля доступа сохраняют текущий секрет. Пароль и заголовок не заполняются из ответа API. Сохранение блокирует повторную отправку, изменение полей и закрытие формы; ошибка остаётся в форме для исправления.

Создание выполняется через `POST /api/integrations/sources`, редактирование — через `PATCH /api/integrations/sources/:code`. Форма отправляет настройки источника и полный набор потоков одним запросом. Сервер сохраняет источник, потоки, права системного автора и аудит в общей транзакции.

Контракт массива `flows`: отсутствующее поле сохраняет подключения; переданный массив задаёт полный набор, отсутствующие потоки деактивируются; пустой массив отключает все потоки. Форма передаёт также ранее существовавшие потоки с актуальным `isActive`. Неизменённая конфигурация сохраняется при временно отсутствующем обработчике; изменение конфигурации проверяется серверным реестром.

## Состояние обмена

Таблица показывает состояние отдельно для каждого подключённого потока:

| Состояние                | Условие                                                                     |
| ------------------------ | --------------------------------------------------------------------------- |
| «Выключен»               | Выключен источник или поток                                                 |
| «Есть проблема»          | Есть код ошибки и отсутствует успех либо ошибка не старше последнего успеха |
| «Работает»               | Есть успешная обработка и нет актуальной ошибки                             |
| «Ожидает первого обмена» | Нет успеха и актуальной ошибки                                              |

При проблеме выводятся безопасный код и пояснение. Для известных ошибок есть отдельные тексты; для остальных используется общее сообщение. Более поздний успех убирает отображение старой ошибки.

Состояние строится по `isActive`, `lastSuccessAt`, `lastErrorAt` и `lastErrorCode`. «Работает» отражает результат последнего обмена, а не проверку сетевой доступности в текущий момент.

`warehouse.receipts` принимает входящие события. `orders.customers` опрашивает OData по расписанию модуля заказов. Состояние обоих потоков отображается общим компонентом.

## Входящие ключи

После выбора источника отображаются его ключи и адреса событий активных потоков с входящими действиями:

```text
/api/integrations/sources/:code/flows/:flowCode/events
```

Выпуск ключа доступен для активных потоков с действием `event:create`. В форме выпуска выбираются разрешённые потоки, название и срок действия. Полный ключ показывается однократно после создания; список содержит его метаданные. Отзыв требует подтверждения и обновляет данные панели.

Потоки опроса определяются по пустому списку `incomingActions`; для них адреса входящих событий не формируются, а выпуск ключа недоступен.

## Журнал событий

Журнал содержит входящие события общего inbox. Фильтры и подписи поддерживают `PENDING`, `PROCESSING`, `PROCESSED`, `SKIPPED`, `FAILED`. По умолчанию выбраны ожидающие события. Страница содержит 25 записей.

Отображаются источник, объект или номер документа, сведения результата, состояние, число попыток, код ошибки и время следующей попытки для `PENDING`. Код результата пропуска сопоставляется с пояснением о неподключённом или выключенном складе.

Повтор доступен для `FAILED` и `SKIPPED` через `POST /api/integrations/events/:id/retry`. Общая блокировка мутаций предотвращает повторную отправку из панели. Обновление журнала заново загружает данные; оно не запускает опрос 1С. История запусков исходящего опроса хранится в модуле-владельце потока.

## Связи складов

Для источника с `warehouse.receipts` действие «Склады 1С» открывает список связей и форму добавления. Вводятся точный внешний ID склада и активный склад ESoft. Сохранённая связь закрепляет соответствие внешнего ID выбранному складу.

Поток приходов проверяет связь и активность склада при импорте. Пропущенные события доступны в журнале для повторной обработки после настройки. Правила применения документов находятся в модуле складских приходов; панель управляет подключением и повтором события.

## Тестирование

Из корня репозитория:

```powershell
npm run test --workspace frontend -- src/modules/integrations
npm run build --workspace frontend
```

Тесты проверяют доступ, режимы авторизации, сохранение источника, выпуск ключей, ограничения потоков опроса, связи складов, состояния обмена, журнал и отмену устаревших загрузок. HTTP-контракты и транзакционные гарантии дополнительно проверяются тестами бэкенда.
