# CSS приложения

## Общие стили

`src/index.css` содержит базовые правила документа и подключает общие переменные
из `shared/ui/tokens.css`. Цвета и скругления общих элементов задаются через эти
переменные; специфичные цвета диаграмм и предметных статусов остаются в своих модулях.

Приложение использует системный стек шрифтов и не загружает шрифты из интернета.
Если потребуется другой шрифт, его файлы и лицензию следует включить в проект и
подключить локально через `@font-face`. Внешние CSS-импорты и CDN для оформления
не используются: интерфейс должен работать без доступа в интернет.

Стили общих элементов находятся рядом с компонентами:

- `AdminModal.css` — оболочка модального окна; импортируется `AdminModal`.
- `AdminButtons.css` — кнопки и действия таблицы.
- `AppTable.css` — сортировка и интерактивные строки; импортируется `AppTable`.
- `FormField.css` — общие правила полей и ошибок; подключается компонентом `FormField`.
- `AdminFormField.css` — компактный вариант полей через переменные общей базы.
- `Tabs.css` — общая поверхность вкладок оборудования и административных страниц.
- `PageHeading.css` — одинаковое оформление заголовков страниц.
- `Notice.css` — уведомления; импортируется `Notice`.
- `pdf-preview/PdfPreviewShell.css` — оболочка просмотра PDF, доступная также
  состоянию загрузки без подключения самого PDF-просмотрщика.

`AdminPage.css` содержит административную раскладку и подключает общие кнопки
и вкладки. Правила полей находятся в `FormField.css`, таблиц — в `AppTable.css`.

## Стили модулей

CSS страницы может быть точкой входа с `@import` тематических файлов. Например,
`PpePage.css` подключает расположение элементов, карточку сотрудника, журнал,
каталог и нормы. `ShoeSizeRange` и `ClothingSizeGrid` дополнительно подключают
собственные стили при использовании вне страницы.

Оформление формы оборудования и общего расположения страниц создания и
редактирования находится в `modules/equipment-create-form`. Страница
редактирования не импортирует CSS другой страницы.

## Правила размещения

- Общий компонент подключает собственный CSS. Его оформление не должно зависеть
  от посещения другой страницы или загрузки другого модуля.
- Правила страницы используют её классы. Неопределённые глобальные селекторы
  вроде `.data-table td small` в CSS страницы не допускаются.
- Вариации общих элементов задаются классом контекста или модификатором;
  повторное глобальное объявление `.field-error` не используется.
- Разделение файла следует ответственности компонентов, а не фиксированному
  количеству строк. Адаптивные состояния остаются рядом с соответствующим блоком.
- При переносе правил сохраняются специфичность, порядок переопределений,
  адаптивные условия и поддержка `prefers-reduced-motion`.
- Перед новым стилем используется существующий общий компонент или его вариант.
  Универсальный файл со всеми стилями приложения не создаётся.

`npm run lint --workspace frontend` запускает Oxlint и отдельный скрипт
`scripts/check-import-boundaries.cjs`. Скрипт проверяет относительные импорты
и реэкспорты в TS/TSX, динамические импорты со строковым путём и относительные
CSS `@import` с путём в кавычках. Он запрещает зависимости `shared`/`modules`
от `pages` и импорты между разными страницами; тестовые файлы исключены.

Проверка не анализирует неотносительные пути, вычисляемые динамические импорты
или использование CSS-классов без импорта. Эти зависимости контролируются
при ревью.
